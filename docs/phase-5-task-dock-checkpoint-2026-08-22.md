# Phase 5 Task Dock 跨工作流检查点

> 日期：2026-08-22
>
> 分支：`codex/master-roadmap-phase-0-1`
>
> 定位：Phase 5 的全局任务筛选、跨工作流素材缩略图和任务现场恢复检查点；10+20 真实并发压力态与统一状态组件仍待完成。

## 1. 用户现在可以完成什么

- Task Dock 保持一个全局队列，并可按“全部 / 单产品 / 多文件 / 合照 / 抠图”筛选；顶部全局完成度不会被局部筛选误导。
- 每个筛选项显示对应任务数量；筛选只改变列表视图，不暂停、不取消、也不改变后台任务。
- 未产生结果的任务提供“回到现场”，会切换到正确工作流，并恢复该任务提交时的源素材、描述、模型、构图、保真度、输出数与意图锁定。
- 已有结果的任务继续提供“打开结果”，先恢复任务现场，再恢复结果版本。
- 任务缩略图不再只从当前工作流素材域查找；任务来自其他工作流时也会按需读取源素材元数据。
- 若源素材已移入回收站，任务快照仍保留，并明确告诉用户有多少张素材未恢复到当前选择。

## 2. 一致性约束

- “回到现场”以 `job_snapshots` 的不可变提交快照为准，不能用后来被编辑过的当前草稿覆盖历史任务语义。
- 单产品和多文件共享产品素材，但任务筛选、任务参数和草稿现场仍按工作流隔离。
- 任务筛选是纯视图状态；全局进度继续按所有未结束任务计算。
- 源素材元数据最多按 120 个唯一 ID、有界并发 6 个一组读取，避免 Task Dock 轮询造成无界请求。
- 打开历史现场会将该现场写回当前工作流草稿，使刷新或重启后仍回到同一任务上下文。

## 3. UI 与可访问性

- 筛选使用抽屉内横向胶囊，不增加一级导航，也不挤占 Studio 舞台。
- 核心标签和动作全部使用中文；`DURABLE JOB CENTER`、`QUEUE COMPLETION` 仅作为装饰眉题。
- 任务状态变化仍由单独 `aria-live` 区域播报；百分比轮询不会反复抢焦点或朗读。
- 960×600 实测：页面 960×600、Task Dock 590×580，抽屉无整体溢出，筛选栏 589/589 无横向滚动，任务列表是唯一可增长滚动区。

## 4. 验证证据

- 前端 Node：40/40 通过。
- Vite 生产构建通过。
- 浏览器实测：Task Dock 可访问结构正确，五个筛选项可操作并正确更新 `aria-pressed`。
- 960×600 浏览器尺寸检查通过；控制台仅有 Vite 连接 debug，0 error / 0 warning。
- 纯状态测试验证：跨工作流筛选数量、源素材 ID 去重与顺序、不可变 brief/parameters/intent 恢复。

## 5. Phase 5 剩余工作

1. 使用离线处理器完成“抠图 10 张 + 多文件 20 张 + 单产品 1 张”的真实并发、切换、重启和部分失败验收。
2. 素材批量选择、批量移出、排序和 50+ 素材分段渲染。
3. 回收站筛选、保留期时间展示和满足条件后的受控永久清理确认。
4. 空、加载、离线、冲突与部分失败的统一状态组件。
