# Product Atelier 下一阶段：分域素材、任务上下文与可解释学习计划

> 日期：2026-08-22  
> 状态：需求已冻结，尚未实施  
> 来源：用户对 `codex/reliable-batch-workspace` 实机体验的反馈  
> 本轮边界：只记录产品决策、实现方法和验收标准，不修改现有功能。
> 本文为“分域素材、任务上下文与可解释学习”专项计划；完整 UI、工程阶段、测试、时间与发布路线以 `docs/product-atelier-master-execution-plan-2026-08-22.md` 为总纲。

## 0. 结论先行

当前“可靠素材与任务底座”解决了素材落盘、并发、恢复和进度持久化，但还没有形成设计师能连续工作的工作区模型。下一阶段不能只增加按钮，必须同时完成以下五件事：

1. 把一个全局素材池改为三个逻辑工作区：产品素材、合照素材、抠图素材。
2. 每个工作流保存自己的草稿、选择、预览和任务上下文；切换模式不清空、不串台。
3. 增加可恢复的素材移除、回收站和引用保护。
4. 把“对比”从不明所以的常驻入口改成结果评审中的情境功能。
5. 明确每段描述、每条知识、每次反馈到底被谁使用、产生了什么影响；抠图需区分“去背景”和“按语义选物”。

物理素材仍只保存一份内容寻址文件。所谓三个工作区是逻辑归类和不同任务上下文，不复制源文件、不新增第二套素材存储。

## 1. 当前实现事实

### 1.1 素材与任务

- `/api/assets` 当前返回同一个共享素材池，四种工作流都从这里选图。
- 前端虽然分别保存四种模式的选择与参数快照，但素材列表没有按工作语义分域。
- 任务已经持久化并可后台并发；Task Dock 是全局任务视图。
- 返回某一模式时，还没有稳定恢复该模式的“草稿 + 当前任务 + 当前预览 + 当前评审位置”完整上下文。

### 1.2 对比

- 当前对比只支持“当前内存中的一张原图”和“当前查看的一张结果图”。
- 左侧导航可以在没有可对比内容时直接进入空页面。
- 用户无法先选择“原图 vs 结果”或“版本 A vs 版本 B”，也没有清楚的首次使用引导。
- 因此当前实现具备滑杆组件，但没有完成可发现、可理解的产品流程。

### 1.3 描述、抠图与反馈

- Studio 顶部描述会被写入 `brief.user_request`，提交时随任务保存，并触发知识编译。
- 单产品、多文件和合照生成链会读取任务知识与 Prompt；本地批量抠图链只执行 `remove_bg_hd()` 与透明边界裁切。
- 当前抠图执行器没有读取 `brief`、自然语言描述或知识规则。因此“只保留两个汉堡”虽然被保存了，但没有影响抠图结果。
- 当前 BiRefNet 工作流解决的是“前景与背景分离”，不是“理解一句话后只选择指定物体”。画面里其他前景被一起保留，首要原因是能力与交互语义不匹配，不只是模型边缘质量问题。
- 反馈会写入本地账本的 `feedback`，随后触发记忆建议合成；但界面没有清楚显示反馈针对哪个结果、会不会触发本次重做、形成了什么待审核知识，因此用户无法判断反馈是否有用。

## 2. 目标工作区模型

### 2.1 三个素材域、四个工作流草稿

| 逻辑素材域 | 使用工作流 | 共享范围 | 独立保存的上下文 |
|---|---|---|---|
| 产品素材 | 单产品、多文件 | 两者共享素材成员关系 | 单产品草稿与多文件草稿分别保存选择、描述、参数、预览和活动任务 |
| 合照素材 | 合照拆分 | 只在合照工作区显示 | 选择、主体识别结果、拆分预览、活动任务和评审位置 |
| 抠图素材 | 批量抠图 | 只在抠图工作区显示 | 选择、对象选择/蒙版预览、活动任务、输出预览和评审位置 |

### 2.2 双层任务视图

- **当前工作区视图**：只显示当前工作流的草稿、运行中任务、最近结果和预览。
- **全局 Task Dock**：显示全部工作流的运行队列和总体进度，可按工作流筛选。
- 发出抠图任务后切换到多文件，抠图继续后台运行；返回抠图时恢复原选择、描述、蒙版/结果预览和任务进度。
- 已提交任务必须使用不可变快照，用户随后修改当前草稿不能改变正在运行的任务。

## 3. P0：分域素材与持久工作流上下文

### 目标

让用户在多个任务之间连续工作，不再从一个越来越大的素材池里反复找图，也不因模式切换丢失现场。

### 实现方法

1. 在现有内容寻址素材层之上增加逻辑集合，不复制物理图片：
   - `product`
   - `group`
   - `cutout`
2. 增加素材集合成员关系，记录排序、加入时间、归档/移除状态。
3. 增加四个工作流草稿状态：`single`、`multi-file`、`group-split`、`cutout-batch`。
4. 草稿至少持久化：
   - 已选 `asset_id`；
   - 描述和结构化意图；
   - 模型与参数；
   - 当前活动/最近 `job_id`；
   - 当前查看的结果、版本与预览位置；
   - 抠图的对象选择或蒙版草稿。
5. 后端作为恢复真相源；`localStorage` 只允许做瞬时缓存，不能承担跨重启唯一状态。
6. 模式切换时先保存当前草稿，再加载目标模式草稿；异步请求必须有版本保护，禁止晚返回的数据覆盖当前模式。
7. 当前工作区只渲染相关任务；Task Dock 保留全局视角并提供工作流筛选。

### 验收标准

- [ ] 单产品和多文件看到同一个产品素材集合，但各自的选择、参数和预览互不覆盖。
- [ ] 合照素材不会出现在产品或抠图工作区；抠图素材也不会出现在其他工作区。
- [ ] 抠图任务运行时切到多文件可以继续导入、选择和提交新任务，两类任务并发且互不阻塞。
- [ ] 返回抠图后，原素材、选择、描述、任务进度和预览仍在。
- [ ] 刷新前端、关闭并重启应用后，四个工作流草稿和最近任务从后端恢复。
- [ ] 任务提交后再修改草稿，不会改变已入队任务的素材、描述和参数快照。

## 4. P0：素材删除、归档与恢复

### 目标

让用户可以整理素材工作区，同时不破坏运行中任务、历史记录和学习证据。

### 实现方法

1. 素材卡支持单选、多选和批量操作。
2. 主操作命名为“移出当前工作区”，操作后进入回收站并显示可撤销提示。
3. 区分三种动作：
   - 取消本次选择；
   - 移出当前逻辑工作区；
   - 永久删除本地文件。
4. 被运行中任务引用的素材不能永久删除；允许从当前列表隐藏，但任务快照仍可读取。
5. 被历史、结果血缘、反馈或知识证据引用的素材只做软删除/归档，保留审计所需文件。
6. 只有引用计数为零时才允许永久清理内容寻址文件；永久删除必须二次确认。
7. 增加回收站视图，支持恢复到原工作区和彻底清理。

### 验收标准

- [ ] 用户可以删除单张或批量移出素材，并在误操作后撤销或从回收站恢复。
- [ ] 删除素材不会让正在运行的任务失败，也不会破坏历史结果预览。
- [ ] 同一物理素材同时属于两个逻辑集合时，从一个集合移除不会影响另一个集合。
- [ ] 有引用的文件不会被物理删除；无引用文件确认后可以彻底清理。

## 5. P1：对比功能重做

### 目标

让用户无需研究即可理解“比较什么、怎么比较、比较后做什么”。

### 实现方法

1. 取消或弱化左侧常驻“对比”入口；默认从结果查看或 Result Review 中进入。
2. 只有存在可比较对象时显示对比操作，否则显示明确条件和行动按钮，而不是空白功能页。
3. 提供两种明确场景：
   - 原图 vs 当前结果；
   - 版本 A vs 版本 B。
4. 进入时自动带入当前任务、当前结果和原图；用户也可以在版本条中更换两侧对象。
5. 首次使用显示一句中文引导：“拖动中线，查看轮廓、材质和构图发生了什么变化。”
6. 提供滑杆、并排和快速闪切三种检查方式，默认只显示滑杆，其他方式渐进展开。
7. 对比结束后可以直接执行：采用、需要调整、设为终稿、返回当前任务。

### 验收标准

- [ ] 没有结果时，用户不会误入一个无法使用的对比页。
- [ ] 从结果页一次点击即可进入“原图 vs 当前结果”，无需再次找图。
- [ ] 用户能够选择两个历史版本进行比较，标签以中文说明双方身份。
- [ ] 对比后的采用/调整结论绑定到具体版本，不会只写入模糊的会话级反馈。

## 6. P1：抠图语义拆分与模型路线

### 目标

避免把“去除背景”和“只保留指定物体”伪装成同一个功能，让用户的自然语言要求真正影响结果。

### 实现方法

1. 抠图工作区提供两个明确模式：
   - **快速去背景**：保留全部主要前景，使用本地 BiRefNet；不宣称理解文字。
   - **智能选物抠图**：根据文字、点击或框选识别指定对象，再生成对应蒙版。
2. 快速去背景模式隐藏或禁用不会生效的画面描述，并明确提示“此模式保留全部前景”。
3. 智能选物模式支持：
   - 输入“只保留两个汉堡”；
   - 在预览图上点击/框选对象；
   - 先展示检测到的对象和蒙版预览；
   - 用户取消多余对象后再正式输出。
4. 模型路线需通过样本评测后选择，候选能力按职责拆分：
   - 文字/点击定位对象；
   - 通用分割生成蒙版；
   - 抠图边缘与透明细节精修。
5. 建立汉堡、包装、饮料、透明容器、毛发/细线、相邻多物体等回归集，分别评测选物准确率和边缘质量。

### 验收标准

- [ ] 快速去背景模式不会让用户误以为文字描述会改变保留对象。
- [ ] 智能选物模式中输入“只保留两个汉堡”，执行前可看到并确认两个目标蒙版。
- [ ] 多余前景不会在未经确认时进入最终透明 PNG。
- [ ] 结果失败时能够区分“对象识别错误”“蒙版边缘错误”和“用户选择错误”，不能统一归因于抠图模型。

## 7. P1：描述、反馈与知识的可解释闭环

### 目标

让用户明确知道文字去了哪里、知识如何介入、反馈会改变本次任务还是未来任务。

### 三层内容必须分开

1. **功能帮助知识**：解释这个功能解决什么问题、如何使用、什么情况下不适用；属于应用帮助系统。
2. **执行知识**：会被本次任务读取并影响 Prompt、模型路由、选物或质量检查的规则与案例；属于创作知识库。
3. **学习证据**：采用、拒绝、调整原因、终稿差异和反例；先进入待审核建议，不直接污染正式知识。

不是每个按钮都要建立知识页，但每个会改变输出的工作流必须有自己的知识域、能力边界和评测标准：

| 工作流 | 需要的执行知识 | 必须显示的执行回执 |
|---|---|---|
| 单产品/多文件 | 产品保真、构图、品牌、包装文字、平台规范 | 使用了哪些规则、Prompt 版本、模型和被锁定内容 |
| 合照拆分 | 主体数量、遮挡、裁切、是否精修、失败判定 | 识别了几个主体、哪些被拆分、哪些需要确认 |
| 快速去背景 | 前景定义、边缘质量、透明输出规范 | 此模式未读取文字，只执行全部前景去背景 |
| 智能选物抠图 | 目标对象定义、数量、排除项、蒙版质量 | 文字解析结果、检测对象、最终采用的蒙版 |
| 结果对比/评审 | 评分维度、终稿标准、版本差异 | 当前比较对象、发现的偏差、反馈绑定的版本 |

### 实现方法

1. 为每次执行记录可检查的 trace：
   - 使用了哪些描述字段；
   - 哪些字段因当前能力不支持而被忽略及原因；
   - 命中的知识页与规则；
   - 最终 Prompt/结构化选物指令；
   - 模型与工作流版本；
   - 结果与反馈的血缘关系。
2. 任务入队前显示一句核心回执，例如：
   - “已将‘保留两个汉堡’用于智能选物，检测到 2 个目标，等待确认。”
   - “快速去背景不会读取对象数量；将保留全部主要前景。”
3. 反馈必须绑定具体 `generation_id`、`asset_id` 或蒙版版本，不能默认只绑定会话。
4. 用户提交反馈时明确选择或由系统明确说明影响范围：
   - 仅记录判断；
   - 用于本次重做；
   - 形成未来同类任务的待审核知识建议。
5. 提交后展示中文学习回执：记录了什么、作用范围、是否产生建议、在哪里审核、如何撤销。
6. 正式知识仍由用户审核后写入；反例、品牌和工作流作用域必须隔离。

### 验收标准

- [ ] 每个任务都能查看“描述使用情况”和“知识使用情况”，不允许静默忽略用户输入。
- [ ] 用户能区分反馈是改变本次结果、仅存档，还是影响未来任务。
- [ ] 反馈绑定到具体结果/版本，并能从结果回溯到原素材、Prompt、模型和知识来源。
- [ ] 待审核知识建议显示证据、反例、作用域和撤销入口，未经确认不进入正式知识。

## 8. 实施顺序

```text
P0 工作区数据契约与迁移
  → 三个逻辑素材域
  → 四个工作流草稿/预览/任务上下文恢复
  → 素材软删除、回收站与引用保护
  → 对比入口与结果评审整合
  → 抠图“快速去背景 / 智能选物”能力拆分
  → 描述与知识执行 trace
  → 反馈作用域、学习回执与待审核知识
  → 模型评测与全状态 UI 验收
```

不得先做视觉换皮后补数据模型。工作区上下文、任务快照、素材引用和反馈血缘必须先成为稳定契约，UI 才能正确表达它们。

## 9. 下一阶段完成定义

只有同时满足以下场景，才可以称为“可连续工作的成长型工作区”：

1. 用户在抠图中提交任务，立刻切到多文件继续工作；返回抠图时现场、进度和预览全部恢复。
2. 三个素材域互不干扰，单产品和多文件按产品域共享素材但不共享草稿。
3. 用户能整理、移除、撤销和恢复素材，历史任务不会因此损坏。
4. 对比入口只在有明确比较对象时出现，用户一次点击就知道如何使用。
5. “只保留两个汉堡”要么驱动智能选物并展示确认结果，要么界面明确说明当前模式不会使用该描述。
6. 每条反馈都有明确目标、作用范围、学习回执和撤销路径；每个会改变输出的工作流都有对应知识域与评测标准。
