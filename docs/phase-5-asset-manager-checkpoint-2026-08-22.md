# Phase 5 素材管理检查点

> 日期：2026-08-22  
> 分支：`codex/master-roadmap-phase-0-1`  
> 定位：Phase 5 的安全移除、撤销、回收站、恢复和引用解释检查点；批量整理与 Task Dock 跨工作流定位仍待完成。

## 1. 用户现在可以完成什么

- Studio 顶部有明确的“素材管理”入口，不再要求用户发现缩略图 hover 上的删除图标。
- 素材管理随当前工作流切换为产品、合照、抠图三个逻辑域；单产品与多文件明确共享产品素材，但草稿和任务现场仍独立。
- 当前素材支持“移出”，操作后出现可点击的“撤销”；回收站支持查看和恢复。
- “占用”会用中文解释素材仍被多少工作草稿、任务、结果、评审或学习证据引用，以及为什么不能直接物理删除。
- 永久清理没有伪装成普通删除按钮。素材仍受历史引用与 30 天保护期约束。

## 2. 一致性约束

- 素材移出只改变当前逻辑素材域，不删除内容寻址物理文件，不破坏不可变任务快照、生成结果或学习证据。
- 移出共享产品素材时，后端在同一 SQLite 事务内清理 `single` 与 `multi-file` 两个草稿中的旧选择、重排位置并提高 revision。
- 恢复素材只恢复素材域成员关系，不偷偷恢复以前的任务选择，避免用户切回另一个工作流时出现“幽灵选中”。
- 前端在移出后重新读取所有受影响工作流，确保 revision、素材集合和本地选择与账本一致。

## 3. UI 约束

- 素材管理使用情境抽屉，不增加一级导航，也不挤占中央创作舞台。
- 英文只用于 `PRODUCT ASSETS`、`SAFE REMOVE` 等短眉题；共享关系、删除边界、引用原因和恢复操作全部用中文表达。
- 抽屉只保留“当前素材 / 回收站”两个页签；安全解释按需展开，不把任务、血缘和清理规则全部常驻展示。
- 960×600 实测：文档高度与视口一致，抽屉 519×579，底部安全说明可见，列表是唯一滚动区域。

## 4. 验证证据

- 前端 Node：36/36 通过。
- Vite 生产构建通过。
- 隔离账本浏览器实测：导入 1 张素材 → 移出 → 撤销 → 再移出 → 回收站 → 查看占用 → 恢复，全链路成功；控制台 0 error / 0 warning。
- 回收站引用解释实测返回“当前没有历史引用，仍处于 30 天保护期”；恢复后素材回到产品域且保持未选中。
- 后端专项回归确认：产品域移出会同时清理单产品/多文件草稿选择并提升 revision，不可变任务快照继续保留源 asset ID。

## 5. Phase 5 剩余工作

1. 素材批量选择、批量移出、排序和大素材量虚拟化。
2. 回收站筛选、保留期时间展示和满足条件后的受控永久清理确认。
3. Task Dock 按工作流筛选、点击任务回到对应现场、10+20 并发任务的数据态排版。
4. 空、加载、离线、冲突与部分失败的统一状态组件。
