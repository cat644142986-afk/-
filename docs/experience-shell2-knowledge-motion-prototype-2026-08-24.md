# Product Atelier 体验外壳 2.0 与动态知识原型

> 日期：2026-08-24
>
> 状态：交互原型，尚未接入生产前端
>
> 原型入口：`prototypes/experience-shell2/index.html`
> 基线：`236525b` / `checkpoint-2026-08-24-custom-output-root`

## 1. 本检查点解决什么

本原型用于在修改生产 UI 前确认三件事：

1. 最新 Be.run 参考图如何转译为 Product Atelier，而不是继续沿用整高文字左轨。
2. 知识库如何在创作、解释、评审和成长页面中动态出现，而不是只显示文档数量。
3. 动效如何表达任务和知识状态变化，同时保持克制、可中断、可阅读和可降级。

它不调用真实模型、不修改正式知识、不写入用户 SQLite，也不替代 Phase 5 的真实调度与故障注入实现。

## 2. 最新视觉基准

### 2.1 左侧任务栏

- Logo、主导航、任务/设置、主题/头像拆成四段独立区域。
- 主导航与辅助导航使用白色竖向胶囊，不再绘制贯穿窗口的整高栏底色。
- 导航只显示统一线性 SVG 图标；中文意义由 `aria-label`、悬浮提示、页面标题共同承担。
- 当前项是墨黑正圆，内部使用暖黄色图标；未选项不再常驻文字标签或圆角矩形底。
- 一级导航保持创作、会话、成长三个入口；任务中心和设置属于辅助入口。

### 2.2 圆角和材质

| 层级 | 原型值 | 用途 |
|---|---:|---|
| 应用外壳 | 36px | 最新参考图的大曲率外框；生产落地需与 Win32 region 同步实测 |
| 主要面板 | 27px | Studio 舞台、工作流、知识图谱、设置分区 |
| 左侧胶囊 | 29px | 58px 宽的完整半圆胶囊 |
| 普通卡片 | 19px | 任务、知识建议、会话条目 |
| 内部控件 | 14px | 按钮、输入、切换器 |
| 当前导航 | 50% | 46×46px 正圆 |

背景使用灰米色外部留边、暖白壳层、白色面板和少量墨黑锚点；珊瑚橙负责主要动作，黄色只用于深色表面的当前状态。没有采用资料搜索返回的粉色粗野主义或大面积液态玻璃，因为它们与用户最新参考和项目既有品牌方向不符。

## 3. 原型页面与交互

| 页面/情境 | 默认回答的问题 | 可操作内容 |
|---|---|---|
| 创作 Studio | 当前在做什么、知识怎样参与、下一步是什么 | 四工作流切换、生成状态演示、解释抽屉、结果评审 |
| 会话 Sessions | 哪些项目现场可以恢复 | 最近现场、项目阶段、跨工作流状态 |
| 成长 Growth | 系统学到了什么、证据是什么、谁来批准 | Design DNA 节点、解释 trace、批准/拒绝建议、成长动效回放 |
| 设置 Settings | 模型、唯一知识库和交付位置如何管理 | `D:\知识库` 只读展示、自定义成品目录、默认参数 |
| 任务中心 | 部分成功和失败下一步怎么办 | 只重试失败项、永久失败中文解释、成功项锁定、资源释放摘要 |
| 结果评审 | 结果是否可用、反馈影响本次还是以后 | 版本轨、三层判断、对比入口、待审核建议作用域 |

## 4. 动态知识形态

### 4.1 工作流中的知识胶囊

生成演示按真实语义顺序更新：

`理解商品与目标 → 采用已批准知识 → 生成画面 → 品牌一致性核对 → 等待评审`

采用知识时，三张规则卡以一次性聚合动效收拢成“已采用 3 条批准规则”。动效只表达采用动作；规则数量、冲突和原因始终有中文文本。

### 4.2 Design DNA 二维图谱

- 中心是 Design DNA，外围只展示色彩、构图、光线、品牌保护和否决方向五个一级维度。
- 连线仅在页面进入或用户主动回放时绘制，不做持续流动背景。
- 当前选中节点允许一处轻微呼吸环；其他节点保持静止。
- 点击节点后，下方证据摘要立即更新，语义状态不依赖动画结束事件。

### 4.3 可解释 trace

原型固定展示：原始意图、已批准知识、设计决策、终稿反馈。正式实现必须从本地事件账本和不可变任务快照投影，不能由前端重新猜测。

### 4.4 人工审核

- Result Review 只生成“待审核建议”。
- Growth 中用户点击批准后才改变规则状态。
- 拒绝建议会进入审计历史；原型用收拢离场表达，但不会把“消失”当成删除事实。
- 未批准知识不参与未来生成；历史任务保留提交时的知识版本。

## 5. 动效约束

| 类型 | 时长 | 原则 |
|---|---:|---|
| 点击与悬浮反馈 | 160ms | 只使用小位移、颜色和透明度 |
| 组件状态 | 220ms | 可被下一次操作立即替换 |
| 抽屉与页面 | 300ms | 保持来源方向和空间连续性 |
| 知识连线/节点进入 | 420–520ms | 只在进入或主动回放时触发 |

- 主要动画使用 `transform` 和 `opacity`；进度使用 `scaleX`，不通过宽度变化驱动布局。
- 每个视图最多保留 1–2 个运动重点。
- 所有循环、分镜和延时都不能决定真实业务状态。
- `prefers-reduced-motion: reduce` 下立即呈现最终可读状态。
- 图标按钮拥有中文可访问名称，点击区域不小于 43–46px，键盘焦点可见。
- 抽屉和评审层支持 `Escape`、焦点进入、焦点环回与关闭后恢复焦点。

## 6. 响应式门禁

- 1440×900：完整胶囊侧栏、双列 Bento、常驻创作控制。
- 1280×720：减少辅助信息和留白，不缩小核心正文。
- 960×600：顶部知识/任务胶囊收为状态图标，左侧胶囊保留；舞台和主要动作优先。
- 小于 880px 的浏览器调试尺寸允许单一内容区滚动，不出现嵌套横向滚动。

生产落地前还必须进行 Tauri 100%/125%/150% DPI 和多显示器实测；浏览器原型不能替代 Win32 圆角与 WebView 合成验收。

## 7. 进入生产代码前的审批门

原型经用户确认后，才执行以下生产变更：

1. 把左侧导航 DOM 重构为独立胶囊组，并更新统一 token。
2. 先迁移 Shell、Studio 空态和当前真实数据态，不同时改任务后端。
3. 把 Phase 5 部分失败、单项重试和中断恢复状态投影到新任务中心。
4. 真实桌面故障注入完成后，再接 Result Review 和动态知识驾驶舱。

每个生产检查点仍需自动测试、真实 Tauri 测试、独立提交、数据库/源码回滚点和中文证据记录。

## 8. 原型实测证据

本轮使用本地静态服务和 Chromium/WebView 同类渲染环境完成检查，不调用外部服务：

| 尺寸 | 结果 |
|---|---|
| 1440×900 | 外壳 1392×852、36px 圆角；Studio 双列完整；正文区域无横向溢出；只有一个主要生成动作 |
| 1280×720 | 首轮发现右侧主要生成按钮被深色面板裁切；压缩顶栏与辅助卡片后复验，按钮完整位于面板内，页面无溢出 |
| 960×600 | 外壳 940×580；左侧胶囊宽 53px；顶部知识/任务状态收为 52px 圆形摘要；Studio、Growth、设置均无横向或纵向溢出 |

交互检查通过：

- Studio 生成演示可开始、停止并直接进入最终可读状态。
- Task Dock 只重试一个失败项，8 个成功项保持锁定；永久失败继续显示中文原因。
- Growth 知识节点在 960×600 无重叠，批准后待审核数从 2 变为 1。
- Result Review 三层判断与学习作用域正确展开，评审层无内部溢出。
- 抽屉支持 `Escape` 关闭并把焦点还给原触发按钮。
- 浏览器控制台 0 error / 0 warning。

这些证据只证明原型布局与交互契约成立，不替代生产 Tauri 的 DPI、多显示器、真实任务和故障注入验收。
