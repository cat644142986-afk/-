# Phase 5 自定义交付目录检查点

> 日期：2026-08-24
> 分支：`codex/master-roadmap-phase-0-1`
> sidecar contract：`2026-08-24.1`
> 定位：只开放成品交付位置，不迁移应用内部事实源；Phase 5 部分失败与进程中断收口仍是下一检查点。

## 1. 产品边界

- 用户可以在设置页通过原生文件夹选择器调整“交付文件目录”。
- 只有生成成品进入自定义目录；SQLite 账本、任务状态、素材缓存、日志和学习证据继续保存在 `%APPDATA%\ProductAtelier`。
- 新设置只影响之后创建的任务。每个任务把 `output_root` 冻结进不可变参数快照；设置变化、并发执行和进程重启都不能改变已有任务的交付现场。
- 整夹批处理继续把业务交付副本归类到源文件夹旁的 `ProductAtelier-已处理-*`，不被全局交付目录替代。
- 知识库仍只有 `D:\知识库` 一个主库；兼容 Junction 不形成第二份知识数据，也不参与成品存储。

## 2. 路径与发布安全

- 设置时必须通过绝对路径、目录存在、实际写入探针和受保护目录检查；拒绝磁盘根目录、知识库、应用数据目录、程序目录及它们的过宽父目录。
- 新任务入队前再次验证快照目录，磁盘离线或无权限时以稳定错误码和中文说明失败，不进入付费模型调用。
- 模型中间产物仍写入应用内部 `_attempts`；最终发布采用“目标卷隐藏临时文件 → flush/fsync → 同卷原子替换”，支持 C/D 等跨卷交付，不暴露半文件。
- 成品按 `日期 / 工作流 / 任务 / 项目 / attempt` 自动归类，例如：

```text
2026-08-24\04_批量抠图\任务-job_xxx\001-item_xxx\attempt-1\01_cutout.png
```

- 配置保存当前与历史交付根。切换目录后，旧结果仍能经账本资产接口读取；结果路径必须同时满足“账本声明根 + 已保存根 + 真实路径”三重约束。

## 3. 设置页交互

- “本地存储”卡片只增加一个只读路径框、“选择目录”、“打开目录”和一行状态说明，没有把内部数据目录或更多文件操作塞入首屏。
- 核心语义全部用中文说明：成品可调整，内部账本仍由应用保管；新任务采用新目录，运行中任务保持原目录。
- 目录离线时原位显示红色中文原因，并禁用“打开目录”；目录恢复后重新进入设置页即可看到可用状态。
- 路径选择期间按钮有忙碌/禁用状态，目录状态使用 `aria-live` 播报并保留稳定空间，避免布局跳动。

## 4. 自动验证

- Python：完整回归 `100/100` 通过；覆盖路径验证、不可用状态、归类结构、跨卷式原子发布、任务快照冻结、旧结果可读、磁盘离线前置失败和受保护路径拒绝。
- 前端：完整回归 `44/44` 通过；覆盖设置页入口、只读路径、原生选择器调用、中文状态、`aria-live` 和提交前快照捕获。
- 构建门禁：`python -m py_compile`、Vite 正式构建、Rust `custom-protocol` 特性检查与 `git diff --check` 全部通过。
- Rust：共享 `config.json` 已补齐知识路径、当前交付根和历史根字段，避免未来 Rust 写配置时擦除 Python 字段。
- sidecar 构建指纹已包含 `python/storage_paths.py`；PyInstaller 补入 `numba._devicearray`，修复正式包本地抠图运行时缺模块。

## 5. 正式 EXE 故障注入

在隔离应用数据目录和外部 D 盘交付目录中执行，未调用云端模型：

1. 正式 Tauri EXE 使用原生“选择文件夹”对话框保存外部交付目录；设置页立即显示新路径。
2. 运行中把目录移动为离线名：设置页显示“交付目录不存在，或所在磁盘当前不可用”；创建任务返回 `OUTPUT_ROOT_UNAVAILABLE`，没有生成任务、没有模型调用。
3. 恢复目录后，正式 PyInstaller sidecar 完成本地批量抠图，成品进入冻结快照根的 `2026-08-24\04_批量抠图\...\attempt-1`，资产内容接口返回 HTTP 200。
4. 退出并重启正式 EXE：自定义目录仍可用，知识库仍是 `D:\知识库`，Task Dock 恢复两条故障注入任务，已成功结果继续可读。
5. 验收后关闭应用与 sidecar；隔离数据和交付目录已移入 Windows 回收站，可恢复，没有遗留后台进程。

## 6. 下一检查点

继续 Phase 5 稳定性收口，不扩展聊天栏、Shell、Cordis/Node 运行时或子代理：

1. 同一批任务部分成功、部分失败的完整桌面呈现。
2. 只重试失败项，成功项不重复执行。
3. 永久失败的中文原因、建议动作与可追溯错误码。
4. 进程中断后恢复任务现场和 attempt 历史。
5. 退出、取消、失败、重启后的线程、模型会话和临时文件释放门禁。
