## 2026-08-26 实机反馈校准与续作断点

### A. 为什么上一个“闭环计划”不够

`docs/product-atelier-feedback-closure-plan-2026-08-26.md` 只覆盖了一个修复批次，没有把任务生命周期、反馈证据、知识建议、Growth 投影和后续产品阶段串成可持续执行路线。它保留为该批次记录，不再作为续作总纲；从现在起只以本文的状态和执行游标为准。

2026-08-26 两张实机截图证明以下问题仍存在：

1. Growth 显示“待审核建议 0 条”，但流程仍停在“等待终稿反馈”，把全局累计反馈、当前任务反馈和待审核建议三个概念混在一起。
2. 结果已经提交反馈或形成建议后，切换页面、模式、重新水合工作区或重启，反馈表单仍可能重新出现。
3. 点击“完成这张，开始下一项”后，最近结果可能再次自动恢复，创作页又回到 100% 结果态。
4. 用户只能看到“已记录”，看不到这次反馈究竟是：仅成为证据、正在累积重复次数、已经形成待审核建议，还是已经批准并会在下一个任务生效。

### B. 已确认根因

1. `restoreWorkspaceResult()` 在草稿没有活动任务/结果指针时，仍回退到“任意最近有结果的任务”。这违反了“历史可找回，但完成后不自动打扰”的产品语义。
2. `feedbackRecorded`、`feedbackReceipt` 等状态只保存在前端内存；重新水合结果时没有从 `result_reviews`/`feedback` 恢复，因此成功回执不是持久事实。
3. 前端 Result Review 仍主要调用会话级 `/feedback`，没有真正采用已存在的 `/api/jobs/{job_id}/reviews` 结果级契约，也没有稳定传入 `result_asset_id`。
4. `learning_action` 已存在于结果评审数据模型，但后端评审接口尚未把 `record/suggest/regenerate` 编排成可检查的实际动作和结构化回执。
5. Growth 使用全局反馈数量驱动当前任务时间线，并复用最后一次 `knowledgeBundle`；因此全局统计正确时，当前流程语义仍可能错误。
6. “开始下一项”当前依赖异步草稿保存，没有一个原子、幂等的“完成当前现场”领域操作，存在保存竞态和恢复竞态。

### D. 必须先冻结的生命周期契约

在继续增加 UI 前，以下状态必须成为前后端共同契约：

```text
工作流现场
  draft        尚未提交，可编辑素材/意图
  queued       已提交，等待执行
  running      正在执行
  reviewing    有结果，等待或正在评审
  acknowledged 当前结果已处理，仍可停留查看回执
  ready        当前现场已完成，等待下一项

结果评审
  unreviewed   尚未判断
  adopted      可采用
  adjusted     需要调整
  rejected     方向不对

学习动作
  none         只保存结果判断
  record       记录为证据，不承诺形成建议
  suggest      记录证据并返回候选形成/累积状态
  regenerate   记录调整依据并创建本次重做任务（Phase 6B）

建议状态
  no_claim     没有提取出可学习判断
  accumulating 已提取规则但未达到独立会话阈值
  pending      已形成待审核建议
  approved     已批准，从之后的新任务生效
  rejected     已拒绝，保留审计记录
  disabled     曾批准但已停用
```

恢复规则固定为：

- 仅恢复草稿明确指向的 `active_job_id` 或 `current_result_asset_id`。
- 草稿指针为空时不允许回退到任意历史结果；历史结果只能从 Sessions 或 Task Dock 显式打开。
- 切换页面保持当前现场；切换模式加载该模式自己的现场；“开始下一项”会把当前模式置为 `ready`。
- 提交过的评审和反馈必须从账本恢复，不能依赖当前前端内存。
- 结果历史、任务快照、反馈证据和 trace 永远保留；“不再自动弹出”不等于删除。

### F. 对剩余计划的逆推审计与修正

从“可发布成品必须满足什么”反推，原 R0–R9 仍有七个缺口，本次已经写回执行顺序和门禁：

1. **原首个发布检查点漏了桌面壳 P0。** 反馈闭环即使完成，冷启动黑屏和外框锯齿仍会直接破坏成品感；新增 R0A，并要求首个候选包同时关闭 R0A、R1–R4。
2. **原 R7 先比模型、后补能力契约，顺序反了。** 先探测每个模型实际接受的输入、尺寸、质量、透明背景、负向词和返回协议，再做同条件对比；否则 A/B 本身无效。
3. **原 R7 没冻结当前 Prompt 与阶段基线。** 先保存精确 Prompt、知识快照、参考图变换和逐阶段时间，再试 `prompt_v2`、尺寸、精修和路由；每次只改一个变量。
4. **原成本口径只到“单次调用”。** 改为同时报告单调用成本、单输出成本和每张可采用成品成本，失败/废片也计入总费用。
5. **原学习链只看文字反馈。** 增加用户确认终稿差异证据，但必须经过作用域、隐私和人工审核，不能从像素差异自动生成正式规则。
6. **原计划没有付费实验熔断。** 付费 A/B 前先冻结样本数、预计调用数、预算上限和停止条件；先跑零成本单测/历史结果离线评分，未获预算确认不扩量。
7. **原计划没有模型漂移与回退审计。** 模型别名、快照、供应商、能力探测时间和回退原因进入任务快照；能力或价格变化时让评测失效重跑，不静默沿用旧结论。

## 0. 这次要把什么做成

Product Atelier 不是一个“上传图片—选择模型—下载结果”的普通工具。最终产品应当是一套设计师级、可连续工作、可恢复、会解释、能成长的本地创作系统：

1. 用户可以同时处理多个工作流，切换页面不会丢失素材、草稿、任务、预览和评审位置。
2. 任务在后台可靠并发，逐项显示进度、失败原因、重试与恢复状态。
3. 每个工作流只暴露真正会影响结果的输入，不允许保存了描述却在执行时静默忽略。
4. 每次结果、修改与反馈都可以形成证据，但知识建议必须由用户审核后才影响后续生成。
5. 功能持续增加时，主界面仍保持安静、克制、易理解；高级能力按需要展开，不把所有信息同时铺满。
6. UI 达到设计师愿意长期使用的完成度：高级但不炫技，英文只做质感装饰，核心信息和操作用中文表达。

完成标准不是“按钮都能点击”，而是用户能在真实批量工作中自然理解、稳定操作，并明确知道系统为何这样生成、反馈将产生什么影响。

## 2. 不可妥协的产品与工程原则

1. **工作不中断**：切换模式、刷新和重启不能清空已保存现场；已提交任务使用不可变快照。
2. **功能与语义一致**：输入项只有在执行链实际读取时才显示；不支持的能力明确说明边界。
3. **一个屏幕一个主任务**：每个主界面最多一个主要 CTA，常显决策组不超过三个，其余进入渐进展开区。
4. **状态有上下文**：不只显示百分比或红点，要显示“3/12 正在抠图”“2 项等待重试”等可理解状态。
5. **危险操作可恢复**：素材先软删除，支持撤销和回收站；有引用的内容不得静默物理删除。
6. **知识不会偷偷接管**：AI 只能提出带证据的建议，用户审批后才成为生效规则，必须支持撤销。
7. **中文负责表达，英文负责气质**：核心名称、解释、错误与按钮用中文；英文仅用于短标签、分区眉题和少量状态装饰。
8. **不再叠加补丁层**：正式 UI 只维护一套 token 和一套当前样式；历史 CSS 逐步退役，不新建 `v56/v57...` 覆盖文件。
9. **先契约后界面**：数据模型和交互状态先冻结，再开始生产 UI，避免页面好看但无法支撑连续任务。
10. **验收靠真实场景**：每阶段都要用真实图片、批量任务、重启恢复、多分辨率和错误场景验证。

### 3.1 一级导航

左侧一级导航压缩为三个工作空间，图标和文字都保留：

| 入口 | 核心职责 | 不再承担的职责 |
|---|---|---|
| Studio / 创作 | 素材、描述、参数、任务与当前结果 | 不展示完整历史和所有知识明细 |
| Sessions / 会话 | 按项目、日期、工作流查找任务和结果，恢复现场 | 不作为普通素材库 |
| Growth / 成长 | 查看证据、知识建议、审批、编辑与撤销 | 不直接执行生成任务 |

底部保留两个辅助入口：主题、设置。`对比`不再是一级导航；它属于结果评审中的情境操作。Logo 只作为品牌标识，不响应缩小或切换工具栏。

### 3.2 全局与局部状态

- **全局 Task Dock**：跨工作流显示全部队列，点击后定位到对应工作流和任务。
- **当前工作区**：只显示当前模式的素材、草稿、活动任务、最近结果和评审位置。
- **四个工作流草稿**：单产品、多文件、合照拆分、批量抠图分别保存。
- **三个素材域**：单产品与多文件共享产品素材；合照与抠图各自独立。
- **物理文件只存一份**：分域是逻辑成员关系，不重复复制源文件。

### 3.3 核心用户路径

```text
导入素材
  → 在当前工作流保存草稿
  → 配置会影响结果的最少参数
  → 提交不可变任务快照
  → 后台并发执行，用户可切换到其他工作流
  → 回到原工作流恢复进度、素材和预览
  → 进入结果评审（使用 / 调整 / 方向不对）
  → 必要时进行原图/版本对比
  → 选择是否把反馈提交为知识建议
  → 用户在 Growth 审批后，规则才影响后续任务
```

## 4. 最终 UI 方案

### 4.1 整体框架

- 窗口是一块完整、不透明的暖灰米色画布；四角圆角与 Win32 窗口区域精确对应，不能露出底层窗口。
- 外框圆角目标值为 `24px`；Win32 region、WebView 根容器和内部背景必须使用同一几何基准，只允许为抗锯齿保留经实测的 1–2px 安全差。
- 采用参考图的克制 Bento 布局：清晰网格、大块留白、少量深色锚点卡片，不照搬健身仪表盘内容。
- 主框架由 `72px 左侧栏 + 弹性创作区 + 320–384px 控制区` 组成；窗口宽度不足时，右侧控制区变为抽屉，不挤压画布。
- 页面默认不出现双重滚动条。桌面主尺寸下右侧控制区不滚动；高级参数进入抽屉或分步层。低高度窗口只允许一个明确的主滚动容器。

### 4.2 左侧栏

- 宽度目标 `72px`，与主背景融合，不使用包裹整列的白色浮动胶囊和明显边框。
- Logo 视觉尺寸约 `44–48px`，交互命中区不小于 `44×44px`，但不可点击。
- 导航图标 `20–22px`、统一 Lucide 线性风格、`1.8px` 左右描边。
- 激活态通过深色圆形/圆角方形底与一处橙黄强调表达；非激活态保持安静，不能每个图标都带卡片。
- 一级导航最多三个；主题与设置置底，连接状态缩成一个有中文悬浮说明的状态点。
- 键盘焦点清楚可见，点击目标不小于 `44×44px`。

### 4.3 顶部栏

- 高度目标 `68–72px`。
- 左侧只保留当前页面/项目的短标题和一句必要状态，不再同时堆叠大问候、品牌口号和解释句。
- 中部/右部保留两项：Knowledge 状态、Task Dock 状态。默认以紧凑胶囊显示，点击才展开详情。
- Task Dock 必须显示有语义的中文，例如“3 项进行中 · 1 项失败”，不能只显示 `45%`。
- 红黄绿视觉圆点按 macOS 比例收小到约 `12px`，命中区 `28–32px`，间距 `8–10px`，距右侧 `22–24px`。
- 系统按钮 hover 可以显示轻量符号，但不放大、不跳动。

### 4.4 Studio 主界面

```text
┌ 左栏 ┬──────────────────── 创作工作区 ────────────────────┬── 任务控制 ──┐
│      │ 工作区短标题  素材数量  添加/管理                    │ 工作流选择     │
│      │ [仅在该模式有效时显示的创作描述]                     │ 核心参数 ≤ 3组 │
│      │                                                      │                │
│      │       素材 / 蒙版 / 运行进度 / 结果预览主舞台          │ 知识影响摘要   │
│      │                                                      │                │
│      │ [紧凑的当前任务/最近结果上下文条]                     │ 唯一主 CTA     │
└──────┴──────────────────────────────────────────────────────┴──────────────┘
```

具体规则：

- 中央舞台是第一视觉层，不能被顶部说明、底部两张大卡片和右侧大黑卡同时夹击。
- 移除常驻的 `CURRENT FLOW` 与 `CREATION LEDGER` 两张大底卡，改为一条可点击的上下文状态条；完整信息进入 Task Dock 或 Result Review。
- 素材为空时只展示一个清楚的导入动作和简短格式说明；有素材后切换为素材网格或预览，不再保留大面积空态文案。
- 工作区标题显示当前逻辑域，例如“产品素材 · 多文件处理”；同时显示素材数量、选择数量、添加和管理。
- 描述框仅在执行链会读取时显示；快速去背景模式隐藏自然语言框并说明“只分离前景，不理解物体数量”。
- 右侧默认只显示：工作流、模型策略摘要、最多三组核心参数和一个主 CTA。高级参数、模型详情、知识来源进入抽屉。
- 一次只突出一个主要动作：未选择素材时是“添加素材”，已就绪时是“开始生成/开始抠图”，运行中是“查看任务”。

### 4.5 四个工作流的界面差异

| 工作流 | 素材逻辑 | 主舞台 | 核心控制 | 提交后保持 |
|---|---|---|---|---|
| 单产品 | 与多文件共享产品素材，选择 1 张 | 单图大预览 | 画面目标、保真度、输出数 | 当前原图、结果版本、评审位置 |
| 多文件 | 与单产品共享，支持批量多选 | 网格 + 每项状态 | 统一策略、并发/输出摘要、例外覆盖 | 选择、逐项进度、部分成功结果 |
| 合照拆分 | 独立合照素材域 | 合照 + 自动识别对象/裁切框 | 拆分对象、输出规则、确认框 | 识别框、修正、拆分结果 |
| 批量抠图 | 独立抠图素材域 | 原图、蒙版与透明结果 | 快速去背景 / 智能选物、边缘处理 | 目标对象、蒙版、逐项结果 |

单产品不是“多文件只能选一张”的重复入口：它承担单图精修、更多画面控制和版本评审；多文件承担统一策略、批量并发和个别失败管理。两者共享素材，但交互密度不同。

### 4.6 Task Dock 与任务进度

- Task Dock 是从顶部打开的全局抽屉/侧层，不强占 Studio 常驻面积。
- 顶部提供“全部 / 单产品 / 多文件 / 合照 / 抠图”筛选。
- 每个任务显示：工作流、素材缩略图、完成项/总项、当前阶段、预计剩余/耗时、失败数和下一动作。
- 每个子项显示离散状态：等待、准备、上传、推理、后处理、完成、失败、取消。
- 支持取消、暂停、重试失败项、定位到工作区；危险操作与普通操作分开。
- 进度变化使用轻量动画；状态文本通过 `aria-live` 只播报有意义变化，避免连续百分比骚扰。

### 4.7 Result Review（结果评审）

结果完成后不再只弹一个小反馈条，而进入可继续创作的评审层：

1. 大尺寸显示当前结果，左侧/底部可切换版本。
2. 第一层只问三个中文选择：“可直接使用”“需要小幅调整”“方向不对”。
3. 第二层根据选择显示原因标签，例如构图、主体、文字、质感、边缘、数量、品牌感。
4. 用户可以选择“立即修改本张”或“只用于以后”；两者不能混在一起。
5. 显示本次任务实际使用的模型、Prompt 摘要、知识规则和被锁定意图，形成可追踪回执。
6. 若提交学习，明确显示“已形成 1 条待审核建议”，并提供前往 Growth 的入口。

### 4.8 对比

- 对比只在存在两个可比较对象时出现。
- 默认方式为拖动滑杆；侧边并排和 A/B 切换作为次级方式。
- 支持“原图 vs 当前结果”和“版本 A vs 版本 B”。
- 第一次使用显示一句简短引导；没有对象时不显示入口，也不允许进入空页。
- 对比位置、缩放和当前版本随工作流草稿保存。

### 4.9 素材管理与回收站

- 素材卡支持单选、多选、移出当前域、软删除、查看引用和恢复。
- 普通界面用“移除”表达，回收站用“永久删除”表达；删除后提供即时撤销。
- 被运行任务或历史结果引用的素材只能从工作区隐藏，不能破坏任务血缘。
- 素材超过一定数量后才出现搜索、排序和筛选，少量素材时不增加工具栏噪音。
- 50 张以上网格使用虚拟化或分段渲染，缩略图预留尺寸，避免布局跳动。

### 4.10 Growth / 成长

- 默认只展示“待审核建议”，不是知识文档总数仪表盘。
- 每条建议必须显示：来源结果、用户反馈、适用工作流、建议规则、证据数量和预期影响。
- 操作包括批准、编辑后批准、拒绝、稍后处理和撤销。
- 已生效规则可按工作流、品牌、产品类型查看，并支持停用。
- 系统不能把一次主观反馈直接升级为全局规则；需要范围选择与证据阈值。

### 4.11 设置与 DIY

设置采用分区页签或侧栏，不使用一条无限长页面：

- 模型与 API：模型注册、能力标签、密钥状态、余额/可用性检查。
- 知识与隐私：知识路径、学习审批策略、导出/清空。
- 存储与任务：素材目录、缓存、并发上限、自动恢复。
- 外观：主题预设、强调色、主表面色、深色模式、中央舞台衬图、标题/装饰文字。

DIY 外观要求：

- 提供 3–5 套高质量预设，再开放强调色和背景素材替换；默认预设必须完整好看，不能把设计责任转移给用户。
- 所有修改实时预览，但保存和取消清楚分开。
- 支持恢复默认、导入/导出主题 JSON；自定义图片要有裁切、透明度和对比度保护。
- 自定义文字只允许替换装饰语和工作区副标题，核心功能名称不可被改到难以识别。

### 4.12 与参考图的对应关系

| 参考图特征 | Product Atelier 的转译 | 不照搬的部分 |
|---|---|---|
| 左侧导航融入整块框架 | 72px 安静导航轨，只有激活项形成视觉锚点 | 不复制健身产品图标与白色悬浮胶囊 |
| 上部大卡 + 下部 Bento | 中央素材/结果舞台为大卡，任务与评审以情境层承载 | 不把统计卡片填满空位，不制造假仪表盘 |
| 深浅卡片形成节奏 | 结果评审或任务摘要使用一块深色锚点，其余保持暖白/米色 | 不让每个功能都拥有独立重阴影卡片 |
| 大面积留白 | 减少常驻说明、参数和统计，给素材和结果留下视觉空间 | 不用“空白”掩盖缺失功能；需要时通过抽屉提供深度 |
| 统一圆角和细线图标 | 24/20/16/12px 圆角层级，Lucide 20–22px 统一描边 | 不使用超大 Logo、超大红绿灯或混用多套图标 |
| 高级、安静的首页 | 默认状态只回答当前任务、素材、进度和下一步 | 不把模型、知识数量、Prompt、历史和设置全部首屏化 |

参考图用于校准构图、密度、层级和质感，不用于决定 Product Atelier 的功能。每个卡片是否存在，必须由设计工作流的真实任务证明。

## 5. 视觉与交互设计规范

### 5.1 视觉方向

- 采用暖中性背景、墨黑正文、珊瑚橙强调与少量暗色锚点卡片。
- 使用极简/瑞士网格的秩序感，但保留温暖材料感；不采用与现有品牌冲突的蓝色企业仪表盘或通篇玻璃拟态。
- 阴影只用于表达层级，不用于装饰所有卡片；同一屏幕最多三层 elevation。
- 视觉重点顺序：当前素材/结果 > 主操作 > 任务状态 > 知识解释 > 装饰信息。

### 5.2 Token 基准

| 项目 | 目标值 |
|---|---|
| 外框圆角 | 24px |
| 主面板圆角 | 20–22px |
| 普通卡片圆角 | 16–18px |
| 输入/按钮圆角 | 12px |
| 胶囊 | 999px |
| 间距体系 | 8 / 12 / 16 / 24 / 32px |
| 左栏 | 72px |
| 顶栏 | 68–72px |
| 右控制区 | `clamp(320px, 24vw, 384px)` |
| 图标 | 20–22px，统一线性风格 |
| 红绿灯 | 12px 视觉，28–32px 命中区 |
| 正文 | 14–16px，辅助文字不小于 12px |
| 控件命中区 | 桌面至少 44×44px |

颜色必须以语义 token 管理：`surface/window/card/raised`、`text/primary/muted/inverse`、`accent/primary/soft`、`status/success/warning/error/info`，组件不得散落硬编码颜色。

### 5.3 动效规范

- 微交互 `120–160ms`，组件状态 `180–220ms`，面板进出 `240–300ms`。
- 仅优先动画 `transform` 与 `opacity`，避免用宽高/阴影做大范围持续动画。
- 动效表达因果：点击后控件向来源方向响应，任务完成从进度自然转到结果，不做无意义漂浮。
- 动画必须可中断，并支持 `prefers-reduced-motion`。
- hover 不能承载唯一信息；所有能力都能通过点击或键盘获得。

### 5.4 文案规范

- 标题直接说当前目标，如“批量抠图”“等待选择素材”，不堆砌品牌口号。
- 错误信息写清原因与下一动作，如“素材服务未启动，正在重连；你可以稍后重试”，不暴露纯接口错误给普通用户。
- 英文只用于 `ASSET WORKSPACE`、`RESULT REVIEW` 等短眉题，不能让用户依赖英文理解功能。
- 高风险操作必须写清对象和影响，禁止只有“确定/取消”的无上下文对话框。

### 5.5 响应式与 DPI

- `1920×1080`、`1440×900`：保持中央舞台 + 常驻右控制区。
- `1280×720`：压缩留白与辅助说明，右侧只保留核心分区，不缩小正文。
- 约 `960×600` 或更窄：右控制区变为可关闭抽屉；主舞台优先，避免嵌套滚动。
- Windows 100%、125%、150% DPI 均验证非最大化、最大化、最小尺寸和多显示器切换。
- 长中文、英文文件名、错误信息都要验证截断和可展开查看。

## 6. 完整执行阶段

各阶段必须独立提交、测试和验收。未经上一阶段验收，不进入会掩盖问题的视觉精修。

### 阶段 0：冻结基线与恢复能力加固（P0，预计 3–5 小时）

**目标**

让当前版本可随时回滚，并消除部分迁移、旧 sidecar 与发布包不同步风险。

**实现方法**

1. 记录当前提交、分支、数据库 schema、便携版哈希和桌面快捷方式目标。
2. 创建实施前 tag 与数据库备份；在 `ROLLBACK.md` 写明恢复路径。
3. 将“v2 表存在但 ledger_meta=1”的情况写成幂等恢复逻辑和测试，不再人工改 marker。
4. 构建脚本强制重建 Python sidecar，校验 sidecar 与源码版本/接口清单一致。
5. 启动时执行 schema、关键表、外键和 sidecar 健康检查，失败时阻止误写并给出中文恢复提示。

**验收**

- 全新库、v1 库、正常 v2 库、部分 v2 库均可迁移/恢复且数据不丢。
- 便携版重启后 `/api/health`、`/api/assets` 与 schema 版本一致。
- 回滚演练能在 15 分钟内恢复当前可靠版。

### 阶段 1：交互契约与可点击原型（P0，预计 4–8 小时）

**目标**

在写生产 UI 前，冻结最终信息架构、页面状态和关键交互，避免继续做完再让用户找冲突。

**实现方法**

1. 输出桌面 1440×900、1280×720 和窄屏三种线框。
2. 输出 Studio 四模式、Task Dock、Result Review、素材管理、Growth、设置的页面状态矩阵。
3. 为每个按钮写明：出现条件、输入、状态改变、失败结果、返回后的恢复位置。
4. 制作一套高保真主界面与一条完整任务路径原型。
5. 用户只需审批一次整体方向和关键取舍；细节按本文 token 执行。

**验收**

- 所有一级入口都能用一句话说明价值。
- 四种工作流的上传、任务和结果逻辑不再复用同一个空壳。
- 任意页面都能回答“我在哪里、系统在做什么、下一步是什么”。
- 通过原型后才允许重构生产 UI。

### 阶段 2：schema v3 与工作区数据契约（P0，预计 6–10 小时）

**目标**

为分域素材、草稿恢复、回收站、对比和学习追踪建立单一事实来源。

**实现方法**

1. 设计并迁移逻辑集合、集合成员、工作流草稿、草稿素材选择、软删除/回收站、评审和 trace 数据。

### 阶段 7：抠图语义重构与模型质量评测（P1，预计 12–24 小时，模型评测另计）

**目标**

解决“只要两个汉堡却保留其他前景”的根因，并让用户知道不同能力的边界。

**实现方法**

1. 将抠图拆为两种明确模式：
   - 快速去背景：对所有前景去背景，不显示语义描述。
   - 智能选物：根据文本/点选/框选定位目标，再分割并允许蒙版确认。
2. 建立候选路线：grounding/检测 → 分割 → 边缘细化；不能只替换同类去背景模型后宣称支持语义选物。
3. 建立真实电商测试集：食品、多物体、透明材质、毛发、阴影、包装字、相似目标、目标数量。
4. 评测目标召回、误保留、边缘质量、耗时、显存/内存和失败恢复，形成模型能力标签。
5. 智能选物结果先显示目标框/蒙版供确认；置信度低时不自动提交最终图。

**验收**

- 快速模式不会接受一个不会被读取的描述框。
- 智能模式能在含多个前景的测试图中按“两个汉堡”选择正确对象，并支持用户修正。
- 评测报告说明每个模型适合什么，不只写“高质量”。
- 模型失败可回退到手动点选/框选，不让整批任务作废。

### 阶段 8：可解释知识闭环与 Design DNA（P1，预计 12–20 小时）

**目标**

让系统真正从用户工作中成长，同时保持可控、可解释和可撤销。

**实现方法**

1. 为四个工作流建立独立知识域和能力契约；只有相关知识能进入该模式 Prompt。
2. 每次任务保存“用户原始意图 → 结构化意图 → 采用知识 → 编译 Prompt → 结果 → 反馈”的完整 trace。
3. Result Review 只形成待审核建议；Growth 展示证据、适用范围和预期影响。
4. 支持规则批准、编辑、拒绝、停用、版本化与撤销。
5. 加入最小证据阈值、冲突检测和局部优先级：用户当次明确意图 > 项目/品牌规则 > 个人通用规则。
6. 提供学习回执：“本次采用 3 条已批准规则，忽略 1 条冲突规则”，并能展开原因。

**验收**

- 用户能追溯一条规则来自哪次结果和哪条反馈。
- 未批准建议绝不影响生成。
- 撤销规则后新任务不再采用，历史任务仍保持可复现。
- 同一输入能用保存的快照复现 Prompt、模型和知识版本。

| 里程碑 | 包含阶段 | 用户获得的真实价值 | 预计投入 |

1. 先做恢复与原型。
2. 再做 schema/API 和可持续工作台。
3. 然后做结果评审和能力语义。
4. 再完成成长闭环。
5. 最后进行完整视觉精修与正式发布。

## 9. 明确不做的错误路线

- 不再通过新增 `vXX-fixes.css` 和大量 `!important` 修补冲突。
- 不把所有模型、参数、知识统计和任务详情同时塞进主界面。
- 不保留一个没有上下文的常驻“对比”入口。
- 不让不同工作流继续共享同一个无分类素材视图。
- 不用 localStorage 作为素材、任务或知识的最终事实来源。
- 不物理删除仍被任务、结果或知识证据引用的素材。
- 不显示执行器不会读取的描述或参数。
- 不把快速去背景模型包装成理解自然语言的智能选物。
- 不让一次反馈自动升级为全局知识规则。
- 不用一个分辨率、一张截图或一次成功运行代替完整验收。

## 10. 正式版之后的扩展路线

这些功能有意义，但必须建立在 M4 正式版稳定之后：

1. **模型注册与自动评测平台**：按任务、成本、速度、保真和失败率自适应路由。
2. **品牌/项目模板**：把已批准知识、输出规格、文字保护和视觉偏好组合成可复用项目模板。
3. **无限画布**：把素材、版本、蒙版、批注和任务节点放进可视创作图谱；它应复用现有账本和任务系统，不另造数据孤岛。
4. **自动化配方**：允许把稳定工作流保存为“导入 → 处理 → 评审门槛 → 导出”的批量方案。
5. **外部工具与插件层**：按能力接入 ComfyUI、第三方图像 API、PSD/设计工具和自定义 Skill，但所有结果仍写回同一 trace。
6. **协作与项目权限**：多人审核、规则提议、项目知识范围和版本审计。

后续扩展遵守同一原则：新增能力可以增加深度，不能增加主界面的常驻噪音；通过情境入口、命令面板、抽屉与渐进披露承载复杂度。

## 12. Definition of Done

Product Atelier 只有同时满足以下条件才算本轮完成：

- 真实素材和任务可跨工作流、刷新、重启与崩溃恢复。
- 用户可并发处理多个工作流，不需要等待一个任务结束再开始下一个。
- 每种工作流有与其目标一致的素材、输入、预览、任务和结果流程。
- 任务有全局与局部进度，失败可理解、可定位、可恢复。
- 素材可整理、删除、撤销、恢复且不破坏历史血缘。
- 对比、反馈和知识学习具有明确上下文与低学习成本。
- 抠图区分去背景与语义选物，输入不会被静默忽略。
- UI 信息量受控、左栏融合、圆角不透底、右侧无嵌套滚动，达到参考图要求的秩序和高级感。
- 主题 DIY 不破坏可读性，关键交互满足键盘、焦点、对比度与 reduced motion 要求。
- 数据库、源码、sidecar、便携版、文档、Git 标签和快捷方式指向同一个正式版本。

## 13. 正式版后产品增长总路线（G0–G8）

本节吸收 2026-09-01 独立产品增长规划及随后关于无限画布、SKU 商品语义、精准局部处理和情境式创作副驾的讨论。原资料只作为方案来源；本节是进入 Product Atelier Git 后的唯一执行版本。写入计划不代表已经启动画布、Agent、模型下载或付费实验。

### 13.1 最终产品定位

Product Atelier 的长期定位收敛为：**以无限画布为核心，以商品档案为事实源，以精准局部处理为关键能力，以质量验收、配方生产和审美学习形成闭环的商品视觉工作系统。**

生产链固定为：

```text
商品真相 → 素材与版本 → 画布与快捷操作 → ROI/Mask 精准处理
  → 结构化质量验收 → 局部返修 → 配方化批量交付 → 审美偏好学习
```

- 一级导航继续只有 `Studio / 会话 / 成长`，不为智能选物、扩图、质检或副驾新增一级页面。
- `Studio` 是无限工作空间与有限导出画板；现有快速去背景、白底图、合照拆分和智能选物保留为快捷操作与画布命令，不再各自扩张为数据孤岛。
- `会话` 继续承载任务、版本、Result Review、失败恢复和配方运行。
- `成长` 继续承载 Design DNA、质量趋势、待审核知识和偏好证据。
- 创作副驾随情境唤起但不常驻占屏；它编排现有能力，不替代图像模型、任务引擎或人工质量判断。

### 13.2 不可破坏的架构合同

1. SQLite schema、素材血缘、任务快照和 trace 继续是事实源；画布 JSON 只是受账本管理的工作文档版本。
2. 画布只保存 `asset_id/result_id`、位置、尺寸、旋转、层级、裁剪、蒙版版本和画板规格，不把原图 Base64 复制进文档。
3. 大图在画布使用代理预览，实际处理和导出读取原始分辨率；代理丢失可重建，不成为唯一资产。
4. 快捷操作与画布必须调用同一命令注册表、后端 API、幂等键和任务恢复链，不维护两套抠图、生图或保存实现。
5. 外层 ROI 定义最大可写范围，内层 Mask 定义真实修改像素；未授权区域由本地合成器恢复原像素，严格模式的选区外差异必须为 0。
6. 每次操作生成新版本，不覆盖原图；撤销、重做、比较、失败恢复和来源追溯贯穿画布、任务与 Result Review。
7. 付费生成、批量重做、文件删除和正式知识写入继续显示影响范围与次数并要求确认；失败不自动追加付费调用。
8. Agent、OCR、SAM、OpenCLIP、扩散和 3D 运行时均不得成为核心手动功能的单点依赖。

### 13.4 阶段顺序与验收

#### G0：增长前置门禁（12–24 小时）

- 保持 `959c235...` 正式 artifact 和当前用户数据不变；为增长开发建立独立回滚点与测试数据目录。
- 先完成或明确冻结默认生图质量稳定性、公开 NSIS 外部签名条件和 `app.js` 拆分边界，不让画布开发掩盖当前遗留。
- 冻结 `CanvasDocument / Artboard / Layer / Operation / Mask / ROI / ProductProfile / QualityIssue / Recipe` 的最小合同草案。
- G0 只允许文档、合同测试和独立原型准备，不向正式 Studio 插入画布库或新模型。

门禁：主工作树干净；回滚与数据隔离可验证；用户明确开始增长路线；没有未结算的付费调用或隐式模型下载。

#### G1：画布核心与统一命令（70–110 小时）

当前状态（2026-09-02）：`G1A` 与 `G1B` 已关闭并正式发布。Fabric.js 7.4.0、schema v4、不可变画布版本、统一命令注册表、分段图层、重启恢复和逐像素原始素材导出均已进入 `674feb92109c5115b0efb111b017ab6298fc7267` 正式便携版；下一阶段不再重复 G1 门禁。

`G1A` 先用 24–40 小时建立独立 Fabric.js 原型，只验证无限工作空间、有限画板、图层、选择/变换、撤销/重做、重启恢复、一个现有快捷命令复用，以及 200 张代理图和 4K 原图引用的内存/缩放/序列化。原型不读取用户正式账本、不进入 `src/`、不改变正式包。

只有 G1A 通过后才进入 `G1B`：冻结正式数据合同，将画布接入 Studio、SQLite 文档版本和统一命令注册表。Fabric 真实性能不达门槛时才启动 Konva 替代 PoC；禁止同时维护两套画布。

门禁：快捷模式和画布模式产生同一任务/结果事实；重启恢复同一画板、图层和版本；画板导出尺寸逐像素正确；DPI、键盘、焦点、大素材和正式 WebView 门禁全部通过。

#### G2：SKU 商品数字分身（35–60 小时）

- 建立商品档案：SKU、类目、规格、材质、品牌色、包装文字、Logo、平台规格与批准参考图。
- 商品组件覆盖核心主体、容器/盘子、瓶盖、标签、配件、阴影和背景；每项可设为“必须保留 / 可选保留 / 允许修改 / 禁止修改”。
- “只选菜 / 菜+盘子 / 整个组合 / 全部拆出”必须是可见、可恢复的用户选择，不能让模型暗中决定。

门禁：用餐盘、透明瓶、包装文字、多产品合照验证；材质、数量、文字和组件保护进入不可变任务快照与 trace；历史档案版本可追溯且不被新修改覆盖。

#### G3：精准局部处理与扩图（50–90 小时）

- 在画布接入框选、点选、画笔保留/删除、反选、边缘调整、蒙版预览与恢复。
- 云端图像编辑 provider 可以读取选区周边上下文，但返回结果必须由本地合成器按 Mask 落图。
- 扩图默认锁定原画板，只允许写新增区域；接缝融合使用显式、可见、可调宽度的过渡带。

门禁：严格模式选区外像素差异为 0；撤销返回操作前指纹；失败不污染原版本；每次付费修改在执行前展示调用次数、写入范围和输出规格。

#### G4：情境式创作副驾第一阶段（30–50 小时）

- 载体是 `Ctrl+K`/顶部命令入口、可收起的右侧抽屉和画布内情境提醒，不新增常驻聊天首页。
- 读取画布、选区、SKU、任务、质量报告与已批准知识，执行“观察 → 判断 → 询问 → 计划 → 预览”；第一阶段只读和计划预览，不直接修改图片。
- 大脑模型通过 provider 契约可替换，不绑定 DeepSeek 或任何生图 API；Pydantic AI 仅为候选框架。
- 默认“标准”主动程度，只在歧义、失败、付费风险和质量硬伤时出现；普通鼠标/画布事件先走本地规则，不持续消耗 token。

门禁：副驾离线或失败时全部手动功能可用；不建立第二套长期记忆；删除、付费、批量重做与知识写入仍由本地审批；没有完成 G1–G3 或没有用户重新确认 Agent 预算时不得启动 G4。

#### G5：质量总监 2.0 与局部返修（45–75 小时）

- 在现有确定性检查上增加数量、SKU 保护组件、包装文字、Logo、品牌色、透明材质、裁切和平台安全区。
- 每个问题输出结构化 `QualityIssue`：严重度、证据、问题区域、未验证轴和建议动作；问题区域可直接转为 G3 的 ROI/Mask。
- 固定真实验收集覆盖食品+器皿、多产品、透明/反光、包装文字、细线和复杂阴影；分别记录误报、漏报、耗时、体积和适用范围。

门禁：无法验证的轴明确显示“未验证”；通用 IQA 分数不能单独判定商业合格；失败默认不自动付费重做。

#### G6：创意配方与渠道套装（40–70 小时）

- 将批准的画布过程保存为版本化配方：输入、SKU 约束、操作步骤、质量门禁、失败策略和输出规格。
- 一个 SKU 可批量生成白底主图、详情页素材、Banner、竖图和透明 PNG，继续复用 Task Dock、部分失败、失败项重试和成功项不重复。
- G4 副驾此时才可在用户确认后执行注册工具、建立配方和批量任务；普通用户不接触节点图。

门禁：配方可复制、升版、回退和安全停用；批量运行可中断恢复；每张结果可追溯配方版本、SKU 版本和实际模型能力。

#### G7：视觉素材大脑（30–55 小时）

- 先做无模型检索：商品、类目、时间、评审、规格、感知哈希去重和历史血缘。
- 只有素材规模证明普通筛选不足后，才增加可选 OpenCLIP + sqlite-vec 语义搜索和以图找图。
- 向量绑定模型版本，可删除重建；卸载可选包不影响素材库与普通搜索。

门禁：搜索结果解释来自元数据、图像相似或评审状态；sqlite-vec 升级前备份并演练索引重建；私密素材不发送到未批准的云端索引。

#### G8：个人审美排序器（30–50 小时，不含数据积累）

- 从 A/B 选择、采用/拒绝、终稿差异和结构化原因生成成对偏好数据。
- 每个主要类目建议至少积累 50 组有效选择后才开始验证；第一阶段静默评估，不改变用户看到的顺序。
- 只有留出集持续优于原顺序且可解释时才允许重排候选；排序器不得批准知识或擅自改图。

门禁：用户可查看排序证据、关闭排序、清空本地模型并恢复原顺序；数据不足或效果退化自动回到不排序。

### 13.6 体积、成本与停止清单

- 当前正式目录 `375681686 bytes`（约 `358.28 MiB`）作为增长基线。每个里程碑主包净增长建议不超过 `100 MiB`，超出必须单独批准。
- Torch、Transformers、OpenCLIP/OCR/SAM/扩散/3D 权重全部使用可选能力包；设置页显示下载大小、磁盘占用、内存/显存、许可证、版本、哈希和卸载入口。
- 云端能力必须显示调用次数和可核实账单证据；没有实际账单时标记成本未知，不以估算冒充实付成本。
- G0–G6 完成前继续停止：堆同类 grounding 模型、默认包内置 GB 级运行时、整套嵌入 ComfyUI/InvokeAI/miniPaint、节点编辑器、常驻大聊天栏、多人协作、插件商店和 3D 主入口。
- 任何新能力不得为智能选物、扩图、对比、质检或副驾增加一级导航，也不得静默修改已批准知识。
