# 生图质量与速度零成本基线（2026-08-30）

## 本检查点关闭的缺口

- 生图 Prompt 明确冻结为 `prompt_v1`，每个阶段同时保存知识注入前的 `base_prompt`、最终 `compiled_prompt`、负向词以及四组 SHA-256；知识证据使用规范化 JSON 指纹，历史任务不会因知识库后来变化而漂移。
- 实际发送给供应商的参考图记录编码方式、JPEG 质量、Alpha 处理、尺寸、字节数和 SHA-256。该指纹对应真实请求字节，不把素材路径或图像内容写入报告。
- VLM、参考图编码、供应商提交、轮询、下载、解码、本地增强、抠图、暂存、正式发布和端到端完成分别记录耗时；失败 trace 记录失败阶段和错误类型。
- 当前 LK `/v1/media/generate` 适配器没有返回逐调用费用。trace 明确写入 `billing.status=unavailable`，不再用猜测价格冒充实际成本。模型能力合同只声明当前代码和测试已经核对的请求形状；未知模型标记为 `compatibility-only`。
- 新增只读导出器 `tools/export_generation_baseline.py`。默认对 job ID 做 SHA-256 截断，不导出 Prompt、用户输入、图片或 API Key；导出的 `workflow.complete` 才是端到端时间，各阶段相加只作诊断，不能与端到端时间重复计算。

## 当前历史账本事实

在不打开图片、不读取 Prompt、不调用外部接口的前提下，对本机现有账本做了一次隐私化只读盘点：

- 10 个历史任务；
- 7 条可能计费的 VLM/生图 trace，但 0 条带实际价格；
- 2 条已提交结果评价，其中采用 1、拒绝 1；
- 0 个任务带新 `workflow.complete` 计时，0 个带 `prompt_v1` 快照。

因此旧数据只能证明“发生过调用和评价”，不能反推可靠的 P50/P95、单张费用或每张可采用成品成本。新版 trace 只从后续任务开始积累，绝不伪造旧任务数据。本地盘点 JSON 位于忽略的 `build/` 目录，不进入 Git。

## Prompt v3 与单次生成零付费候选（2026-08-31）

后续只读审计确认，当前已记录 Prompt 阶段的正向文本为 655–799 个字符、负向文本为 303–371 个字符，并且普通单产品/多文件会无条件执行两次完整云端生成。这里的核心风险不是“超过上下文”，而是硬约束被重复软要求稀释，以及第二次完整生成再次解释正确主体。旧 `prompt_v2` 会继续携带原模板，因此不再作为“缩短 Prompt”的主候选。

- `prompt_v3` 不携带旧词堆，按模型档案生成紧凑 Render Plan；原模板仍单独冻结到 trace，确保对照可复现。
- 知识注入限制为最多 6 个意图锁、3 条正向知识、1 条负向知识；意图锁、正向知识和负向知识的字符预算分别为 160/120/80，并有冲突裁剪和 ignored evidence。
- 包装文字与 Logo 被锁定时，负向词明确禁止“文字数字或标志错误”，不再同时发送笼统“文字、logo”。
- `single_pass` 与 Prompt 版本分离；v1/v3、单/双阶段可以分别做单变量实验。
- `PRODUCT_ATELIER_ENABLE_PROMPT_V3` 继续默认关闭；未标记的单次/实验任务仍受 `PRODUCT_ATELIER_ENABLE_SINGLE_PASS` 保护。经过盲评后，只有用户从界面显式选择的 `single_pass` 可以绕过实验门禁，且来源固定写为 `generation_strategy_source=user`，默认仍是 v1/双阶段。
- `experiment-template.json` 现在比较 v1/v3且固定双阶段；新增 `experiment-single-pass-template.json` 比较单/双阶段且固定 v1。两个模板均未授权、调用预算为 0。

trace 合同由此升级为 `generation-baseline-2026-08-31.2`。候选本身不代表真实出图更好；后续付费对照和两轮盲评只授权了显式速度选项，没有授权更改正式默认。

离线回归结果为 Python 共运行 240 项（239 通过、1 项平台预期跳过）、前端 115/115、Vite production build 与 Rust/Tauri locked check 全绿。门禁关闭的候选在 provider 调用前失败；测试门禁开启的单次策略只产生 1 次图片调用，并把跳过精修及零适用账单写入 trace。整个验证过程未连接供应商。

## Prompt v3 Render Plan 离线收口（2026-09-01）

逐路径复核发现，旧 `prompt_v3` 在普通首轮和精修阶段没有把用户本次创作要求写回紧凑 Prompt；这会让“缩短 Prompt”退化成静默丢失用户意图。该缺口现已关闭，并建立可单独检查的 `prompt-v3-render-plan-2026-09-01.1`：

- 用户本次要求在首轮和精修阶段均为最高优先级，不再因切换到 `prompt_v3` 丢失；调整任务继续只修改用户点名的问题。
- 用户填写或 VLM 返回的产品数量会进入不可破坏约束；合照拆分后的单产品裁切固定数量为 1，避免把整组合照数量误带进单个裁切。
- 输出规格同时识别 `requested_resolution`、`resolution` 和 `size`；比例与 2K/4K 信息不会因快照字段形状不同消失。
- 六类意图锁全部保留并做等义短写，正向知识预算从 180 字收紧到 120 字；自动知识可以裁剪，用户明确意图和产品数量不能静默裁剪。
- 每条 `prompt_v3` trace 新增 `prompt_render_plan_version`，可精确追溯生成时使用的结构化计划版本。

新增只读工具 `tools/audit_prompt_v3.py`。它不打开图片、不读取 API Key、不连接供应商，报告不包含原 Prompt、原用户要求或原任务 ID，只保存约束检查、长度和 SHA-256。对 9 个冻结质量输入和本机账本中 9 个历史任务元数据回放均为 9/9 通过；首轮/精修 Prompt 最大长度为 362/364 字，扣除用户原始要求后的自动内容最大为 281/283 字，低于 460 字门槛。忽略目录中的本地报告为 `build/prompt-v3-offline-audit-2026-09-01.json`，SHA-256 为 `97F664F4363164F27DBD52A5B98AEA419380B850728B25C8A445741A67ECF302`。

本检查点全量门禁为 Python 255 项（254 通过、1 项平台预期跳过）、前端 116/116、Vite production build、Rust/Tauri locked custom-protocol check、Python compileall 和 Git whitespace 全绿。整个过程为零付费调用。结论只到“候选已具备付费小样资格”，不等于 `prompt_v3` 已证明比 `prompt_v1` 出图更好；`prompt_v3` 继续默认关闭，正式默认仍为 `prompt_v1 + legacy_double_pass`。

## Prompt v1/v3 付费单变量执行与揭盲结论（2026-09-01）

用户明确授权上一节冻结的 3 输入、最多 12 次图片调用后，已在 `gpt-image-2 + legacy_double_pass + 1:1/2K + fidelity 40` 固定条件下独立执行 `prompt_v1` 与 `prompt_v3`。包装文字/品牌色、精确三件数量和真实透明瓶共形成 6 张双阶段成品；12/12 次调用成功，0 次失败、0 次自动重试、0 次 VLM 调用，全部输出为 2048×2048。聚合站余额从 23.7 降至 23.01，实际减少 0.69 个平台余额单位，平均每次调用 0.0575 单位；接口没有声明币种，也没有逐调用账单，因此不得把该数字擅自写成人民币。

真实发送文本中，v1 正向 Prompt 为 721–792 字、负向 Prompt 固定 371 字；v3 正向 Prompt 为 429–497 字、负向 Prompt 为 52–57 字。v3 本轮双阶段平均 149.88 秒，v1 为 107.48 秒；由于六条链按顺序执行且供应商队列不可控，这只能证明“短 Prompt 没有在本轮自然变快”，不能证明 Prompt 长度会导致模型更慢或更快。

本地确定性门禁为 5 张通过、1 张阻断失败；失败轴是非白边界和严重画布接触。用户在不知道映射时对包装、三瓶数量和透明瓶三行全部选择 B；揭盲后分别对应 `prompt_v3`、`prompt_v3`、`prompt_v1`，即用户偏好为 v3 两组、v1 一组。AI 第一轮在未读取映射时偏好包装 B、三瓶 A、透明瓶 B，揭盲后为 v3 一组、v1 两组；两位评审在包装和透明瓶上意见一致，在三瓶组分歧。

唯一阻断失败揭盲后是 `prompt_v3` 的真实透明瓶：黑色背景、四边严重接触并疑似裁切；同组 `prompt_v1` 通过确定性门禁且被用户和 AI 同时选择。AI 十轴均分为 v1 4.613、v3 3.973；两轮偏好票合计 3:3，但确定性阻断不能用票数抵消。结论是 v3 对程序化不透明包装/数量约束有局部价值，却没有稳定的全局质量收益，也没有速度收益证据，因此不替换正式默认、不提升正式便携版。

正式默认继续为 `prompt_v1 + legacy_double_pass`。下一步只在离线侧设计“材质感知 Prompt 路由”：适合的不透明、数量敏感商品才考虑紧凑约束，透明/反光材质继续走安全基线；在新的明确预算授权前不复跑供应商，也不允许质量失败自动付费重做。A/B 成品、私有映射和原始评分继续留在 Git 忽略目录，脱敏结构化结论位于 `docs/reports/generation-prompt-paid-ab-2026-09-01.json`。

执行后全量源码门禁为 Python 258 项（257 通过、1 项平台预期跳过）、前端 116/116、Vite production build、Rust/Tauri locked custom-protocol check、Python compileall 和 Git whitespace 全绿。仓库中的计划副本已改为“授权已消费、不可执行”，避免另一台电脑把历史授权误当成新的付费许可；原始已授权计划哈希保留在结果报告中。

## 首轮付费单变量实测（2026-08-31）

用户明确授权最多 9 次图片调用后，已完成 `prompt_v1 + gpt-image-2 + 1:1/2K + fidelity 40` 固定条件下的 `single_pass` 对 `legacy_double_pass` 配对实验。3 个高信号输入分别覆盖包装文字/品牌色、精确三件数量和真实透明瓶；每组首次生成同时作为单次成品与双阶段精修输入，因此健康路径只需 6 次调用。透明瓶首次精修出现一次供应商 `RuntimeError`，严格配对重做该组后完成，总计使用 8 次，未动用第 9 次，也没有调用付费 VLM。

首个单次可用结果平均 48.50 秒，双阶段完成平均 99.18 秒；单次策略在健康路径上把图片调用从 2 次降为 1 次，并把等待降低 51.10%。第一轮盲评的 10 轴均分为单次 4.53、双阶段 4.50，商业可用性为 4.40 对 4.33；包装文字组双阶段仅领先 0.02，三件商品打平，透明瓶单次领先 0.09。6 张结果均被判为可直接交付，且都为 2048×2048。本地确定性检查没有阻断失败；透明瓶两种策略都出现相同的主体碰边复核警告，说明第二次精修没有修掉该信号。

首轮数据支持“单次策略值得继续验证”，但不支持切换正式默认；第二轮盲评已经补齐，扩到 9 输入的推广门槛仍未完成。`prompt_v3` 必须另做单变量实验，不能与阶段策略一起切换。完整结构化结果位于 `docs/reports/generation-strategy-paid-ab-2026-08-31.json`。

第二轮由用户在不知道方案映射的情况下独立选择，三组都选择 B 并评价“不错”。揭盲后，包装组 B 为单次策略，三件商品与透明瓶 B 为双阶段，即用户偏好为单次 1 组、双阶段 2 组。第一轮则是双阶段 1 组、单次 1 组、打平 1 组；两轮在包装和透明瓶上出现相反偏好，不能宣称任何一方稳定质量领先。第二轮是总体偏好裁决，没有补造 10 轴分数，也没有把“不错”擅自改写为明确的“可直接交付”。
