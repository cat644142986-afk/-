# Phase 1 UI / 交互契约

日期：2026-08-22<br>
状态：可交互原型，等待产品验收<br>
原型入口：`prototypes/studio-phase1/index.html`

## 1. 阶段目标

本阶段不继续在现有生产界面上叠加样式补丁，而是先固定 Product Atelier 的信息架构、任务状态、操作反馈和视觉密度。原型通过后，再按组件边界迁移进 Tauri/Vite 生产界面。

产品首页的第一反馈必须是“正在创作”，不是“正在配置系统”。核心画面只保留四件事：当前工作流、当前素材、当前创作意图、下一步主操作。模型、并发、失败策略等低频配置进入高级设置。

## 2. 设计原则

1. **中文承担语义，英文承担质感。** 标题、按钮、错误和结果判断必须用中文；`WORKFLOW`、`RESULT REVIEW` 等英文只作为低权重装饰标签。
2. **任务和素材都不能因切换工作流而消失。** 单产品与多文件共享产品素材池；合照拆分、批量抠图各有独立素材池、选择、草稿、视口和结果。
3. **运行任务全局可见。** 用户切走工作流后，任务继续并发运行；顶部任务状态和 Task Dock 随时可查看、定位、重试或取消单项。
4. **反馈不是一句“成功”。** 每个结果都要支持对比、判断、修改和学习回执；只有用户确认后，偏好才进入待审核知识建议。
5. **渐进披露。** 默认只显示会显著影响结果的控制项；高级参数不挤占主工作区。
6. **状态优先于装饰。** 所有颜色和动效必须表达选中、运行、成功、警告或失败，不制造无意义噪声。
7. **同一图标体系。** 结构性图标使用统一线性 SVG；不使用 emoji 充当导航或功能图标。

## 3. 布局契约

### 3.1 桌面窗口

- 参考视口：1440 × 900。
- 最低桌面验收：1280 × 720。
- 外窗圆角：24 px；实际发布版由 Win32 窗口区域和 CSS 容器共同实现。
- 左侧导航：74 px，融合在同一窗口底色中，不使用独立悬浮胶囊外框。
- 顶部状态栏：68 px；左侧放上下文标题，右侧只放知识状态、任务状态和系统窗口按钮。
- 右侧控制区：理想宽度 354 px，可在 320–374 px 内自适应。
- 主工作区与控制区之间使用单层 12 px 间距，不套娃式堆叠卡片。
- 桌面高度足够时，右侧控制区禁止出现内嵌滚动条；低频选项进入高级设置。
- 视口窄于 1180 px 时，右侧控制区变为抽屉，主工作区保持可操作。

### 3.2 视觉密度

- 主屏同时可见的大标题不超过 2 个。
- 同一功能只出现一个主按钮。
- 卡片内说明原则上不超过两行。
- 英文眉题字号 10–11 px、字距放大、低对比；不抢中文核心信息。
- 红黄绿窗口按钮按 macOS 视觉尺度处理：圆点直径约 12 px，间距约 8 px；不承担应用功能。

## 4. 工作流与素材隔离

| 工作流 | 素材域 | 上传规则 | 默认处理 | 切换后恢复内容 |
|---|---|---|---|---|
| 单产品 | `product` | 可上传多张，但一次选择一张进入精修 | 单图、多版本 | 选中素材、创作描述、参数、预览位置、结果版本 |
| 多文件 | `product` | 与单产品共享产品素材，可多选 | 每张独立生成、并发执行 | 多选集合、每项进度、失败项、批量参数 |
| 合照拆分 | `group` | 独立素材池，可上传多张合照 | 先识别对象，再选择拆分对象 | 当前合照、对象框、选择结果、拆分任务 |
| 批量抠图 | `cutout` | 独立素材池，可上传多张 | 去背景与按描述选物分开 | 素材、选物描述、遮罩预览、每项结果 |

重要边界：抠图中的“只保留两个汉堡”不是普通背景去除问题，而是**对象选择 / 分割约束**。界面必须明确区分“去背景”和“按描述选物”，并将最终送入模型的对象约束展示给用户确认。

## 5. 页面状态矩阵

### 5.1 Studio 主工作区

| 状态 | 画面 | 可执行操作 | 失败/恢复 |
|---|---|---|---|
| 空素材 | 上传引导 + 支持格式 | 上传、拖入、从素材库选择 | 上传失败显示在对应文件，不清空已成功项 |
| 有素材未选 | 素材网格 + 管理入口 | 单选、多选、删除、撤销 | 删除先进回收站，可撤销 |
| 已选待提交 | 创作描述 + 最少核心控制 | 开始任务、进入高级设置 | 参数无效在原位置解释，不弹技术英文 |
| 运行中 | 每项进度、总进度、预计状态 | 切换工作流、打开 Task Dock、取消单项 | 切走不停止；重启后从任务账本恢复 |
| 部分失败 | 成功结果保留，失败项独立标记 | 重试失败项、修改失败项参数 | 不要求整批重跑 |
| 已完成 | 最近结果入口 + 结果数量 | 打开结果评审、导出 | 结果与任务快照关联，不被下一任务覆盖 |

### 5.2 Task Dock

| 状态 | 必须显示 | 操作 |
|---|---|---|
| 排队 | 工作流、素材数、排队位置 | 提高优先级、取消 |
| 运行 | 单项/总进度、当前阶段、可理解的预计状态 | 定位工作区、取消单项 |
| 部分失败 | 成功数、失败数、人话原因 | 仅重试失败项、查看详情 |
| 完成 | 结果数量、完成时间 | 打开结果、导出 |
| 恢复 | “从任务账本恢复”标记 | 检查状态、重试未完成项 |

### 5.3 结果评审

结果评审是成长系统的入口，不是小型 toast。

| 决策 | 本次结果 | 知识系统 |
|---|---|---|
| 可直接使用 | 标记为采用，可进入导出 | 形成正向证据，但仍需满足累计与审核门槛 |
| 需要微调 | 创建当前结果的新版本 | 修改内容与长期学习分开确认 |
| 方向不对 | 保留失败样本与原因 | 形成待审核反例，不自动污染全局规则 |

必须显示“学习回执”：系统理解了什么、将影响本张还是未来任务、是否已写入待审核建议、用户如何撤销。

### 5.4 对比功能

对比入口只能在至少存在一个原图—结果对时启用。首次使用时给出一步提示：“拖动分界线比较原图与结果”。对比支持：

- 拖动分界线；
- 原图 / 结果清楚标注；
- 适配画布缩放；
- 从历史版本选择对比对象；
- 对比结束直接进入结果判断。

若没有可比较结果，入口必须说明条件，而不是显示一个无法理解的空页面。

## 6. 关键交互契约

| 控件 | 出现条件 | 点击结果 | 错误表达 | 恢复行为 |
|---|---|---|---|---|
| 工作流按钮 | 始终 | 切换对应独立工作区 | 无 | 恢复该工作流素材、草稿、视口和任务 |
| 素材管理 | 有素材 | 多选、移除、删除、回收站 | 指向具体文件 | 撤销恢复原分组与顺序 |
| 主操作按钮 | 输入满足当前工作流 | 创建不可变任务快照并后台执行 | 中文摘要 + 查看详情 | 可重试失败项，不复制成功项 |
| 顶部任务状态 | 有排队/运行/失败任务 | 打开全局 Task Dock | 显示失败数量 | 重启后从任务账本恢复 |
| 知识状态 | 当前工作流存在适用规则 | 展开“本次采用哪些规则” | 规则冲突给出选择 | 任务快照保存实际采用版本 |
| 打开最近结果 | 有结果 | 进入全尺寸结果评审 | 无结果时隐藏或禁用并解释 | 返回原工作区位置 |
| 高级设置 | 始终 | 打开模型、并发、失败策略等 | 字段原位说明 | 保存到工作流级偏好 |

## 7. 任务并发与一致性

- UI 不直接把“批量”理解为串行循环；任务层需要有父任务和不可变子任务快照。
- 并发数由调度器根据模型端点、配额和机器资源决定，UI 只显示“智能并发”及当前槽位。
- 单项状态至少包含：`queued`、`running`、`succeeded`、`failed`、`cancelled`。
- 切换工作流、关闭窗口或重启应用不改变已提交任务身份。
- 同一任务的结果、反馈、知识版本、提示词和模型版本可追溯。

## 8. 原型覆盖范围

当前原型已经表达：

- 融合式左侧导航；
- 四工作流切换与状态恢复文案；
- 产品素材网格与单项进度；
- 顶部知识 / 任务语义状态；
- 全局 Task Dock；
- 结果评审、拖动对比、三类判断和学习回执；
- 高级设置渐进披露；
- 1280 px 窄屏控制抽屉策略；
- 深色模式与减少动态效果支持。

原型故意不接真实接口、不改变生产界面、不写入数据库。进入 Phase 2 后再实现持久状态与任务域；进入 Phase 5 后迁移生产 UI。

## 9. 验收标准

### 产品验收

- 用户在 5 秒内能看懂：当前在哪个工作流、有哪些素材、任务是否在运行、下一步做什么。
- 四个工作流切换后各自状态不丢失。
- 不查看教程也能理解对比功能。
- 结果反馈明确说明“本次修改”和“长期学习”的区别。
- 主屏没有技术接口名、栈追踪或需要学习的英文核心文案。

### 视觉验收

- 1440 × 900 和 1280 × 720 不出现横向溢出。
- 桌面右侧控制区无内嵌滚动条。
- 左侧导航不是独立外框，和窗口融为一体。
- 红黄绿按钮、Logo、图标和文字层级不过度抢眼。
- 页面保持暖白、深炭、珊瑚橙的产品识别，不采用检索到但不匹配产品的粉色 / 青色模板方案。

### 无障碍与交互验收

- 所有图标按钮有可读名称；键盘可达。
- 焦点清晰，正文和按钮对比度达到 WCAG AA。
- 支持 `prefers-reduced-motion`。
- 运行、成功、警告、失败不仅依赖颜色表达。

## 10. 后续实施顺序

1. 用户评审本原型与契约，冻结信息架构。
2. Phase 2 建立任务域 v3：工作区、素材池、任务快照、任务项、结果版本、反馈与知识候选。
3. Phase 3 接入并发调度、恢复、取消、重试和进度事件。
4. Phase 4 接入模型路由、对象选择式抠图和质量评估。
5. Phase 5 将本原型按组件迁移到生产 UI，并完成窗口圆角和响应式适配。
6. Phase 6 完成长时测试、便携版构建、升级 / 回滚验证和发布验收。
